# 第5课：不同 AI 为什么表现不同

> **本课在课程里的位置**：训练 → 推理过渡。懂了发动机的差异，就要学「按任务选对车」。
> **汽车类比定位**：不同模型 = 发动机的变种；模型选型 = 按路况选车型。

> **配套课件**：[第5课.pptx](第5课.pptx)。正文按课件补充，原有拓展保留。
> **PPT 导航**：第 2–5 页回顾与能力差异；第 6–8 页训练与优化；第 9–11 页角色结构和多轮推理；第 12–13 页影响因素与产品差异；第 14–15 页微调和 RAG；第 16 页总结。

## 前课回顾

Transformer 的注意力支持很多并行计算，但大规模训练和推理仍需要算力与能源；长上下文也有使用边界。

## 内容引入

**3 分钟互动：同题不同答，谁真的更强？**

教师展示同一个问题：

```text
请根据我下周三考试的情况，针对我总是搞混的两个知识点，安排 5 天复习计划。
```

再展示三种假想回答：

1. A 工具给出通用复习建议，但没有问考试范围；
2. B 工具先要求上传老师讲义和错题记录；
3. C 工具生成计划，并标注"考试范围需向老师确认"，还能把自测题按知识点分类。

请学生判断：C 一定是模型本身更聪明吗？还是可能因为产品接了文件问答、题库、检查规则或工具？

本节课要解释：不同 AI 表现不同，可能来自训练数据、模型规模、训练目标、对齐方式、工具能力和产品设计。

## 知识点讲授

### 1. 模型的能力差异

评估一个 AI 是否适合任务不要只看排行榜或宣传语。可以用 3-5 个真实问题做小评测：

- 事实准确性：是否基于正确资料；
- 理解能力：是否抓住任务重点和限制；
- 推理能力：多步骤任务是否可靠；
- 格式遵守：是否按要求输出表格、清单或字段；
- 工具使用：是否知道什么时候联网搜索、调用 RAG、加入上下文或使用代码；
- 安全性：是否保护隐私、避免过度承诺；
- 速度和成本：是否适合高频使用。

PPT 第 5 页按长文本写作、编程、数学推理和视觉理解列举模型，教学重点是“按任务看优势”。具体型号与优势会变化，课堂可对照当次使用说明，不把课件中的型号列表当成永久排名。

例如评测复习助手时，可以用"生成 5 天计划""解释一个易混概念的区别""根据错题统计薄弱知识点""遇到未知考试范围如何处理"等问题进行比较。

### 2. 训练和推理的区别

训练是模型长期学习的过程。模型在大量文本、代码、图片或其他数据上学习规律，通过错误反馈调整参数。

推理是日常使用时模型回答问题的过程。用户输入当前问题，模型基于已有参数、当前上下文和产品提供的工具生成回答。

学生平时聊天通常是在推理，不是在重新训练模型。一次提问会影响当前对话上下文，但不等于模型本身永久改变。

### 3. 机器怎样从数据中学习

可以用最简化方式理解机器学习：

```text
样本 + 目标
  ↓
模型做预测
  ↓
和目标比较，发现错误
  ↓
调整参数
  ↓
在更多样本上反复练习
```

参数不是答案表。它更像模型内部大量可调整的"连接强度"和"判断倾向"。训练会让模型把大量样本中的规律压缩进参数里，从而在新问题上迁移使用。

如果训练数据质量高、覆盖面广、目标设计合理，模型通常更稳定；如果数据过时、偏见多、错误多或某类任务样本少，模型在相关任务上就更容易出错。

#### 从“批改作业”到损失地形（PPT 第 6–7 页）

把学生做作业与模型训练逐项对应：课本和作业 → 样本与目标，作答 → 预测，批改 → 比较结果，错题反馈 → 误差/损失，调整知识 → 调整参数。

再用“在丘陵地形中寻找低处”解释优化：横向坐标表示参数取值，海拔表示误差。训练不断调整参数，希望使损失变小。真实模型参数维度远高于二维图，优化也不保证找到全局最低点；训练误差小还要在未见过的数据上验证。

### 4. 三个训练阶段：预训练 → 后训练 → 偏好优化/强化学习

不同模型版本常常经历几个训练阶段，能力差异很大一部分来自这里：

- **预训练**：在大量文本上学规律。它的训练目标是**预测下一个 token**——这是 GPT 类模型的机制事实（"预测到极致*意味什么*"是第 2 课讲过的未决争议，这里不展开）。预训练后的模型很会续写，但不一定会按指令完成任务。
- **后训练（指令训练 / SFT）**：学"看到任务说明后怎样回答"，更能遵守用户要求、按格式输出。
- **偏好优化与强化学习（如 RLHF）**：用人类反馈在多个候选里选更优的那个，让模型更"听话、好用、安全"，适应多轮对话、拒绝危险请求、标注不确定。这是 ChatGPT 区别于更早 GPT-3 的关键一步。

可以把三者类比为：

```text
基座模型：会读很多书，也会接着写
指令模型：知道老师布置任务时要按要求回答
聊天模型：更适合对话，也更注意安全和礼貌
```

所以，同样叫"大模型"，有的更像续写器，有的更像任务助手，有的更适合多轮学习支持。

#### 角色标记、推理与多轮续写（PPT 第 9–11 页）

后训练的对话材料不仅有正文，还区分 `system`、`user`、`assistant`，以及 `tool`、`developer` 等角色。下面是角色结构示意，实际特殊 token 和序列化格式由模型决定：

```text
system：你是一名天文学知识讲解助手，面向高中生回答。
user：恒星为什么会发光？
assistant：恒星核心的核聚变释放能量，能量向外传递并辐射。
user：核心核燃料耗尽后会发生什么？
assistant：（根据上文继续生成）
```

推理时，产品提供系统指令、用户消息及所需历史，让模型续写助手部分；下一轮再组织新增消息和历史。多轮对话的连续感来自重新提供上下文，不是当场把历史训练进参数。

这里沿用 PPT 的三个教学环节；广义“后训练”通常也包含偏好优化和强化学习，不应把三者理解为严格互斥的分类。

### 5. 能力边界来自数据、规模和目标

模型表现差异常见来源：

1. 训练数据时间边界：模型可能不知道最新政策、报名时间、产品价格、赛事结果或学校通知；
2. 数据质量：错误、偏见、重复和低质量数据会影响能力；
3. 领域覆盖：某些专业任务训练少，表现就可能弱；
4. 模型规模和结构：更大或更先进的模型通常能力更强，但成本更高；
5. 对齐目标：有些模型更重视安全和稳妥，有些更开放，有些更适合代码或数学；
6. 上下文长度：能处理的材料长短不同；
7. 工具调用能力：能否稳定选择工具、填参数、读返回结果。

### 6. 产品差异不等于模型差异

一个产品能做很多事，可能不是因为模型本身"全都会"，而是产品接入了工具：

- 联网搜索让它能回答最新信息；
- RAG、文件问答或资料库工具让它能先匹配老师资料，再把资料加入上下文让模型回答；
- 代码执行让它能统计错题、画图和验证计算；
- 多模态通道让它能看图片、读手写题或听语音；
- 日历和文件工具让它能保存计划、创建提醒；
- 安全审核模块让它能拦截作弊、隐私和高风险请求。

PPT 第 13 页还要求检查**工作流编排与用户交互**：是否检查质量、发现缺陷后是否修复、遇到需要用户决定的事项是否交还决策权。仅列出工具清单不足以解释产品效果。

判断一个 AI 能力时，要问：这是模型能力，还是产品功能，还是外部工具？

一句话收束（也是全课的准确性锚点）：**模型决定能力上限**（靠训练 / 后训练 / 强化学习）；**上下文和驾驭层（Harness）决定这个上限能不能稳定落地**（靠产品工程）。所以同一台模型，包成不同产品，表现可以差很多。

### 7. 微调和"RAG/文件问答后再回答"的区别

学生常会把"让模型学会资料"和"让模型通过 RAG 或文件问答使用资料"混在一起。

微调更像改变模型在某类任务上的行为习惯或领域表达方式，例如让模型更会按某种格式回答、掌握某类客服话术或适应特定领域风格。

"查指定资料后再回答"更像让 RAG 或文件问答先匹配相关资料片段，把相关内容加入当前对话上下文，再让模型基于这些资料回答。复习助手读取老师讲义、错题本和复习范围，更常见的是这种流程，而不是把每份讲义都重新训练进模型参数。

本课按 PPT 的狭义用法，把微调指为：在已完成后训练的模型上，使用领域数据继续训练、修改参数。例如将领域文本中的信息提取为固定字段，小模型也可以针对特定环节训练。它需要数据准备、训练和评估成本，可能牺牲部分通用能力；并不意味着模型能准确背下所有资料。

| 比较维度 | 微调 | RAG |
| ---- | ---- | ---- |
| 参数 | 修改 | 通常不修改 |
| 主要目标 | 适配领域任务、格式或行为 | 回答时取得相关资料 |
| 更新资料 | 通常需再次训练与验证 | 更新知识库及索引 |
| 主要代价与风险 | 训练成本、数据质量、泛化退化 | 检索遗漏、片段过时、增加输入 token |

两种方法可以组合，不是只能二选一。

简单判断：

| 需求 | 更可能使用 |
| ---- | ---------- |
| 让模型按固定格式、风格、任务习惯回答 | 微调或系统提示词 |
| 让模型基于最新公开信息回答 | 联网搜索 |
| 让模型基于老师讲义、错题解析等指定资料回答 | RAG 或文件问答 |
| 让模型统计错题表和生成图表 | 代码或数据工具 |

## 教师答疑参考（附录，不计入 20 分钟）

1. 学生可能会问：同一个模型放在不同产品里，回答会一样吗？

   推荐回答：不一定。产品可能设置了不同系统提示词、工具、知识库、联网能力、安全规则和输出格式。即使底层模型相同，产品设计也会让实际体验不同。

2. 学生可能会问：模型训练数据越多，是不是一定越聪明？

   推荐回答：数据量很重要，但不是唯一因素。数据质量、覆盖领域、训练目标、模型结构、对齐方式和评估方法都会影响表现。大量低质量或过时数据也可能带来错误和偏见。

3. 学生可能会问：微调是不是比 RAG 更高级？

   推荐回答：二者解决的问题不同。微调更适合改变回答风格、固定流程或特定任务习惯；RAG 更适合让模型基于指定资料、最新资料或课程资料回答。复习助手读取老师讲义，通常优先考虑 RAG 或文件问答。

4. 学生可能会问：如果一个 AI 排行榜分数高，我是不是就可以放心用它做所有学习任务？

   推荐回答：不能只看排行榜。排行榜通常只覆盖某些测试维度，和你的真实任务可能不同。更可靠的方法是用自己的 3-5 个真实问题做小评测，观察准确性、依据、格式、工具使用和风险控制。

5. 学生可能会问：为什么有的 AI 不愿意回答某些问题？

   推荐回答：这通常和聊天对齐、安全规则和产品政策有关。AI 产品会限制作弊、隐私泄露、危险行为、过度承诺等请求。拒绝回答不一定是能力不足，也可能是在遵守安全边界。
