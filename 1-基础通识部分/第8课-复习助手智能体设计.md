# 第8课：智能体案例解析

> **本课在课程里的位置**：推理层·自治（收束课）。把前 7 课合成一个可说明、可检查、有边界的智能体方案。
> **汽车类比定位**：智能体 = 自动驾驶车（规划 + 多步 + 反思）；它 = 模型（发动机）+ Harness（整车里发动机以外的一切）。

> **配套课件**：[第8课.pptx](第8课.pptx)。正文按课件补充，原有拓展保留。
> **PPT 导航**：第 2–4 页回顾与设计任务；第 5–7 页需求、架构与 OpenClaw；第 8–9 页记忆和 Skill；第 10 页评估；第 11–15 页得失、能力与责任；第 16 页结束。

## 前课回顾

CoT/ToT/GoT 组织任务过程，PaE/ReAct 编排执行与反馈，MCP 用于标准化接入外部工具。

## 内容引入

**3 分钟互动：复习助手是一条提示词，还是一个系统？**

教师展示案例请求：

```text
下周三有一场考试，我有两个知识点总是搞混。每天晚上大概有 45 分钟复习时间。
请帮我整理重点、安排 5 天复习计划，并给我几道自测题。
```

请学生判断：如果只写一条好提示词，它能完成哪些部分？如果要持续读取讲义、统计错题、记录进度、根据自测调整、写入提醒、保护隐私，它还需要哪些模块？

教师引出本课核心：智能体不是"更会聊天的大模型"，而是围绕目标持续完成任务的系统。

## 知识点讲授

### 1. 用复习助手回顾全课

复习助手把前面几课内容串在一起：

- 它根据上下文生成计划和自测题，提示词影响输出；
- 文字、公式、图片和语音会变成 token、embedding 或其他可计算输入片段；
- 它可能漏条件、算错或被无关信息带偏，需要错误排查；
- 不同模型和产品在规划、出题、工具调用和安全提醒上表现不同；
- 结构化提示词让任务、要求、格式、场景更清楚；
- 复杂复习任务需要 CoT/ToT/GoT 等任务组织方式、PaE/ReAct 执行架构、思考模式，以及 RAG、工具和反馈。

### 2. 复习助手的功能需求（PPT 第 5 页）

先从 PPT 第 5 页提取四类需求：**用户交互**用于澄清目标和接收反馈，**学科知识**用于讲解与出题，**联网搜索和工具**用于取资料或执行操作，**记忆**用于持续记录复习状态。

### 3. 什么是智能体

本课采用的智能体定义：

> 智能体是围绕目标持续完成任务的系统，它把大模型、提示词、规划框架、工具、知识库、记忆、评估、权限和人工确认组织在一起。

智能体不是模型有了主观意识。用一句更准确的话：**智能体 = 模型 + Harness（驾驭层）**——模型外面那圈规划、工具、记忆、评估、权限合起来，就是 Harness。它的能力来自系统设计：模型负责理解和生成，提示词负责约束任务，工具负责查资料和执行动作，记忆保存必要状态，评估和权限控制风险。

Harness 大致做三件事（课堂上记直觉即可）：

- **驾驭（Steer）**：控制方向、速度、何时停止（系统提示词、规则、纠错提示、待办清单）；
- **约束（Constrain）**：权限、沙箱、审批、白名单、审计——这是护栏；
- **整合（Integrate）**：把工具、状态、记忆、协作拼成一个能跑起来的系统。

### 4. 复习助手的基本结构（PPT 第 6 页）

第 6 页把需求映射到架构：用户界面接收输入，PaE/ReAct“大脑”编排大模型，课程知识库用 RAG 提供依据，工具模块可以通过 MCP 接入，记忆保存必要状态。RAG 不是模型本体，MCP 不是思考方式，记忆也不是自动更新模型参数。

一个受老师监管的复习助手可以包含：

| 模块 | 作用 | 风险控制 |
| ---- | ---- | -------- |
| 用户入口 | 接收学生请求和反馈 | 提醒不要输入无关隐私 |
| 任务理解 | 提取考试时间、薄弱点、可用时间 | 信息缺失时追问 |
| 规划模块 | 拆成资料检索、复习安排、自测、反馈 | 步骤要可检查 |
| 模型调用 | 解释、生成、总结、比较方案 | 选择适合任务的模型 |
| RAG/课程知识库 | 检索老师讲义、复习范围、错题解析 | 标注来源和更新时间 |
| 错题记录 | 定位薄弱知识点 | 需授权，少保存敏感信息 |
| 题目生成工具 | 生成自测题和解析 | 防止生成考试答案 |
| 代码/统计工具 | 统计错题分布、时间安排 | 检查统计口径 |
| 日程工具 | 生成提醒或计划 | 写入前人工确认 |
| 安全审核 | 检查作弊、隐私、过度承诺和高风险内容 | 高风险转人工 |
| 反馈与记忆 | 保存进度和常见错因 | 可查看、可修改、可删除 |

### 5. 小龙虾/OpenClaw 案例

为了理解真实智能体系统，可以用"小龙虾/OpenClaw"作为案例。课堂中不要求学生掌握部署、Gateway 细节、插件开发或设备节点，只把它作为一个真实智能体系统的结构样例。

OpenClaw 可以被教学化理解为：一个能连接聊天入口、Gateway、Agent、模型、工具、插件、技能、会话、记忆和设备能力的个人智能体平台。

一个任务的流动可以简化为：

```text
用户在聊天入口提出任务
  ↓
Gateway 接收消息、确认身份和会话
  ↓
Agent 调用模型理解目标并规划
  ↓
模型判断需要工具、插件或技能
  ↓
工具执行并返回观察结果
  ↓
Agent 更新会话、记忆或下一步
  ↓
结果回到用户入口
```

对照 PPT 第 7 页图示逐一定位：外部大模型负责生成与决策，用户界面接收任务，Gateway 连接入口与会话，智能体大脑负责执行循环，数据存储保存记录；文件操作、数据处理、应用使用、系统管理体现对外部环境的操作能力，Skills 封装可复用方法。课件的“长爪子/短爪子”是辅助记忆的类比，不是技术分类或固定实现规范。

这个案例说明：真实智能体不是一个孤立聊天框，而是多个模块协作的系统。

### 6. 对照 OpenClaw 和复习助手

OpenClaw 展示真实智能体可以接入渠道、模型、工具、记忆和设备能力。复习助手则把这些能力限制在学习场景中：

- 入口：学生和老师允许的学习平台；
- 模型：用于理解、解释、规划和生成题目；
- 工具：课程 RAG、错题统计、题库、日历、安全审核；
- 记忆：复习进度、常见错因、学习偏好；
- 权限：读取资料、保存记忆、写入日程都需要授权；
- 评估：准确性、依据、可执行性、隐私和安全边界。

### 7. 四类记忆：存什么、存多久、怎样使用

PPT 第 8 页把智能体记忆分为四类。用复习助手逐一对应：

| 类型 | 存储内容 | 常见载体与生命周期 | 复习助手例子 |
| ---- | ---- | ---- | ---- |
| 工作记忆 | 当前消息、工具结果、任务中间状态 | 上下文窗口、会话缓存；当前任务使用，容量有限 | 本轮 45 分钟限制、刚查出的讲义片段 |
| 情景记忆 | 带时间的具体经历、任务记录与结果 | 日志、文件、数据库；可跨会话保存 | 上次自测哪题做错、当天如何调整计划 |
| 语义记忆 | 提炼后的知识、偏好和经验 | 向量库、知识图谱等；长期复用 | 学生偏好简短解释、已确认的概念知识 |
| 程序记忆 | 完成任务的方法、规则与技能 | 系统指令、工具定义、工作流、Skill；相对稳定 | 先核实考纲，再出题、批改、生成复习卡 |

“工作记忆短期”指当前计算使用的范围；会话日志可以被产品保存，再检索回来，不等于关闭窗口后所有数据必然删除。同一载体也可以承载不同类型记忆，分类依据是用途，不是文件格式。

**存下来不等于已经用上**：系统需要从长期存储中检索相关信息，核查时效，再放入当前上下文。复习助手应只保存必要信息，支持查看、更正与删除；把一次错误答案存成“知识”会在后续不断传播。

### 8. Skill：把任务经验整理成可复用的方法

按 PPT 第 9 页，Skill 可以理解为程序记忆的一种组织形式，包含**任务指令、代码或脚本工具、文档与模板等数据资源**。它不等于新模型，也不保证模型已经学会新知识。

沿用课件“错题复习”示例（下面是设计草案，文件与脚本名称仅为示例）：

```text
名称：错题复习
描述：错题归类并生成复习卡
工具：exercise.py、cards.py
资料：课纲与考纲.docx
方法说明：出题方法.md

1. 读取已授权的课纲与考纲，缺失则先请用户补充。
2. 按出题方法调用 exercise.py 生成范围内练习。
3. 收集用户答案，对照依据批改，记录待老师确认的问题。
4. 将错题与错因交给 cards.py，生成可检查的复习卡。
5. 展示结果；保存学习记录前确认保存范围。
```

Tool 完成一个动作，Skill 组织一类任务的做法；MCP 可以用于接入工具，但 Skill 不必经由 MCP 才能运行。让学生指出示例中的指令、工具、数据和失败处理分别在哪里。

### 9. 面对任务的解法路径

面对一个学习任务，学生可以先判断使用哪条路径：

| 解法路径 | 适用场景 |
| -------- | -------- |
| 直接问答 | 解释一个概念或术语 |
| 结构化提示词 | 生成复习计划、知识卡片、写作提纲 |
| 分步规划 | 安排多天复习、分阶段完成项目 |
| 多方案比较 | 比较按知识点、按错题、按题型复习 |
| 搜索增强 | 需要最新通知、报名时间、公开资料 |
| RAG/文件问答 | 必须基于老师讲义、错题解析或校内资料 |
| 代码/计算工具 | 统计错题、计算时间、处理表格 |
| 人工确认/转人工 | 考试范围不明确、隐私、作弊、正式评价、高风险压力 |

### 10. 评估 AI 输出和智能体过程

评估不只看答案像不像，还要看过程是否可靠：

- 准确性：知识点和计算是否正确；
- 完整性：是否覆盖目标和限制；
- 依据：是否标注资料来源；
- 可执行性：时间和步骤是否现实；
- 格式：是否便于学生使用和检查；
- 工具调用：工具是否选对，参数是否准确；
- 风险：是否涉及隐私、作弊、过度承诺或高风险建议；
- 人工确认：哪些地方需要老师、学生或家长确认。

### 12. AI 时代的得失与人的责任（PPT 第 11–15 页）

PPT 第 11–14 页将技术学习落到使用者的能力：

- **强智能与强依赖**：AI 扩展可完成的任务，也可能让人跳过独立思考和基础练习。学生仍应能解释关键步骤、判断输出是否合理。
- **高提效与低质量风险**：生成更快不等于审查更快；未经核查的答案、代码或资料会积累错误。对交付质量负责，不能只看产出数量。
- **快迭代与快淘汰**：具体工具和型号不断变化，学习目标应包含可迁移的使用方法，而不只是记住操作按钮。

培养三种能力：**沟通能力**——把需求说清楚；**设计能力**——规划方法、流程和标准；**批判能力**——追问依据、检查结果、提出修正。课件中的效率与行业观察用于讨论，不作为“所有新开发者都不会编程”或“人人都能替代团队”的统计结论。

最后让学生回答：这份复习计划谁来确认？错误自测题如何纠正？未经授权的资料能否保存？**人为使用 AI 的行为和结果负责**，不能把最终责任推给智能体。

原课纲的解法路径和设计卡保留为备课拓展；20 分钟核心讲授优先覆盖 PPT 的结构、记忆、Skill、评估与责任。

能力越强，边界越重要。**能做 ≠ 该自动做**——一个重要原则是：**任务风险越高，越应该降低 AI 的自治度、越多地让人来确认**（考试范围、隐私、成绩评价、心理压力等都要转人工）。

用两个核心结论收束整门课：

> ① **模型决定能力上限；上下文和 Harness 决定这个上限能不能稳定落地。**
> ② **人负责选方向、定标准、担责任；智能体负责执行、验证、加速迭代。**

## 教师答疑参考（附录，不计入 20 分钟）

1. 学生可能会问：智能体和聊天机器人最大的区别是什么？

   推荐回答：聊天机器人主要是一问一答；智能体更像一个围绕目标运转的系统，会规划步骤、调用工具、使用资料、记录必要状态、根据反馈调整，并设置权限和人工确认点。

2. 学生可能会问：智能体有记忆是不是更好？

   推荐回答：记忆有价值，但不是越多越好。复习进度、常见错因和学习偏好可以帮助个性化；身份证号、家庭隐私、无关聊天、敏感成绩等不应随意保存。好的记忆设计应该可查看、可修改、可删除。

3. 学生可能会问：复习助手能不能代替老师判断我学得好不好？

   推荐回答：不能完全代替。它可以整理错题、生成练习、给出学习建议，但正式评价、考试范围确认、学习状态判断和高风险问题仍然需要老师、学生本人或家长参与。

4. 学生可能会问：如果要设计一个智能体，最先应该想模型还是工具？

   推荐回答：最先想任务目标和边界。先明确用户是谁、要解决什么问题、输入输出是什么、哪些事不能做，再选择模型、提示词、RAG、工具、记忆和评估方式。

5. 学生可能会问：一个智能体做错了，怎样知道是哪一步出错？

   推荐回答：要保留可检查过程：目标提取、资料来源、工具参数、检索片段、统计结果、生成版本和人工确认点。这样才能判断是资料错、工具错、模型理解错、提示词不清，还是权限边界没设计好。
