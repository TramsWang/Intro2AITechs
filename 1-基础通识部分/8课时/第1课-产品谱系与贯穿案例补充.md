# 第 1 课备课补充：面向高中生的大模型产品谱系与复习助手案例库

> 用途：这是一张“能对应到具体模型、产品或开发工具”的谱系图。产品更新很快，课堂以学生当时能看到的功能入口、所在地区、账号权限和学校规定为准。

## 一、谱系图的总结构：三层，而不是一张功能清单

```text
大模型及相关产品生态
├─ A. 模型层：决定“AI 本身能理解、生成什么”
│  ├─ A1 文本通用模型             ├─ A2 推理模型／思考模式
│  ├─ A3 代码模型                 ├─ A4 视觉语言／文档理解模型
│  ├─ A5 语音模型                 ├─ A6 图像生成／编辑模型
│  └─ A7 视频生成／理解模型
├─ B. 工具层：通常没有面向学生的独立聊天界面，只在一个环节提供能力
│  ├─ B1 文本 Embedding           ├─ B2 多模态／图像 Embedding
│  ├─ B3 Reranker（重排序）       ├─ B4 向量数据库／索引库
│  ├─ B5 文档解析／OCR             ├─ B6 网页搜索 API
│  ├─ B7 代码执行沙箱／计算工具    ├─ B8 外部系统 API
│  └─ B9 MCP 服务与 MCP 工具库
└─ C. 整合／编排层：把模型层和工具层组装成学生或老师可用的高级服务
   ├─ C1 文件阅读／长文档助手      ├─ C2 RAG 知识库产品
   ├─ C3 搜索／深度研究产品        ├─ C4 智能体产品
   ├─ C5 Skills／插件系统          ├─ C6 无代码工作流平台
   └─ C7 开发框架与运行时
```

### 先讲清三层分别是什么

| 层次 | 课堂中的提问方式 | 是否通常能由学生直接打开使用？ | 例子 |
| --- | --- | --- | --- |
| **模型层** | “它擅长处理什么输入，生成什么结果？” | 有时能通过聊天产品选择模型或模式；模型本身通常经由产品提供 | Qwen、DeepSeek、GPT、Claude、Gemini；Seedream、可灵等生成模型 |
| **工具层** | “它为上层产品补上哪一个动作或数据处理环节？” | 通常不能单独当作聊天助手使用 | BGE Embedding、Milvus、PaddleOCR、Tavily、Google Calendar API、MCP Server |
| **整合/编排层** | “谁把模型、资料、工具和流程组织成可完成任务的服务？” | 是，学生与老师最常直接使用或配置的产品 | NotebookLM、Perplexity、ChatGPT Deep Research、Coze、Dify、n8n、OpenClaw |

**一个关键判断：** “搜索”“RAG”“工具调用”“记忆”不是和 ChatGPT、豆包、Coze 并列的品牌；它们是由上述三层组合出来的服务能力。例如，一个知识库问答产品常由“文本模型 + Embedding + 向量库 + Reranker + 提示词”组成。

## 二、每个叶节点可对应的具体模型、产品或工具

### A. 模型层

| 最细类别 | 给学生的白话 | 可放入谱系图的代表模型或产品 |
| --- | --- | --- |
| A1 文本通用模型 | 听懂文字要求，解释、改写、翻译、总结、出题 | Qwen、DeepSeek、GLM、豆包、Kimi、GPT、Claude、Gemini；对应聊天产品如通义、DeepSeek、豆包、Kimi、ChatGPT、Claude、Gemini |
| A2 推理模型／思考模式 | 面对条件多、要比较、要计算的任务，会投入更多中间步骤和自检；通常更慢 | DeepSeek-R1、Qwen 深度思考模型/模式、豆包深度思考、ChatGPT Thinking、Gemini Thinking、Claude extended thinking |
| A3 代码模型 | 读写代码、解释报错、把计算过程写成可执行程序 | Qwen-Coder、DeepSeek-Coder、Claude Code、GitHub Copilot、Cursor |
| A4 视觉语言／文档理解模型 | 看照片、题目、图表、公式、页面布局，再用文字回答 | Qwen-VL、豆包视觉模型、GPT 多模态模型、Gemini、Claude；文档理解产品可见 MinerU、PaddleOCR |
| A5 语音模型 | 听录音、把语音转文字，或把文字读出来 | 讯飞星火/讯飞听见、豆包语音、ChatGPT Voice、Gemini Live、Qwen-Omni、Whisper |
| A6 图像生成／编辑模型 | 根据文字画图，或修改原图的文字、背景、风格和局部内容 | 即梦/Seedream、SeedEdit、Midjourney、ChatGPT Images、Adobe Firefly、Qwen-Image |
| A7 视频生成／理解模型 | 根据文字或图片生成短视频，或概括视频内容和字幕 | 可灵、即梦/Seedance、Sora、Veo；视频理解可用 Gemini、Qwen-Omni、豆包视觉工具 |

### B. 工具层（幕后组件，不把它们当作学生要下载的聊天 App）

| 最细类别 | 在系统里实际做什么 | 代表工具、模型或服务 |
| --- | --- | --- |
| B1 文本 Embedding 模型 | 把一句话或一段讲义变成一串数字坐标，用来寻找“意思相近”的文字 | BGE-M3、Qwen Embedding、Doubao Embedding、OpenAI text-embedding 系列、Cohere Embed |
| B2 多模态／图像 Embedding 模型 | 把图片、图片+文字或音视频片段变成可比较的坐标，用于以图搜图、相似题检索 | CLIP、SigLIP、Qwen-VL Embedding、多模态检索模型；可见于图片素材库与多模态 RAG |
| B3 Reranker（重排序） | 对初步找出的若干资料片段再排一次名，把最相关的证据放到前面 | BGE-Reranker、Qwen Reranker、Cohere Rerank、Jina Reranker |
| B4 向量数据库／索引库 | 保存 Embedding 并快速找相近片段；它存的是“可检索坐标”和关联资料，不负责写答案 | Milvus、pgvector、Elasticsearch Vector Search、Pinecone、FAISS、Chroma |
| B5 文档解析／OCR 工具 | 把 PDF、扫描讲义、图片、表格中的文字和结构提取出来，供模型或 RAG 使用 | PaddleOCR、MinerU、Unstructured、Azure Document Intelligence、火山文档解析 |
| B6 网页搜索 API | 按关键词检索公开网页并返回标题、链接、摘要或正文，供上层产品引用 | Bing Web Search、Google Programmable Search、Tavily、Brave Search API、Serper |
| B7 代码执行沙箱／计算工具 | 在受限环境中真的运行 Python/SQL/表格计算并返回结果，不让模型“凭感觉心算” | Python、Jupyter、E2B Sandbox、Code Interpreter/数据分析沙箱、Wolfram\|Alpha |
| B8 外部系统 API | 让上层产品在授权后读取或修改真实系统，例如日历、网盘、地图、邮件、课程平台 | Google Calendar API、Microsoft Graph、飞书开放平台、Notion API、Amap API、学校 LMS API |
| B9 MCP 服务与 MCP 工具库 | 用统一方式把文件、数据库、搜索、GitHub、地图等工具暴露给模型/智能体；工具库帮助发现和安装这些服务 | 官方 Filesystem/GitHub MCP Server、Playwright MCP、Amap MCP、Smithery、MCP.so、魔搭 MCP 广场 |

### C. 整合／编排层（学生和老师通常直接看到的产品）

| 最细类别 | 它把什么整合成了什么服务 | 代表产品或框架 |
| --- | --- | --- |
| C1 文件阅读／长文档助手 | 模型 + 文件上传/解析 + 当前上下文，完成一次性文档阅读、摘要和问答 | Kimi、豆包 AI 阅读、ChatGPT 文件上传、Claude Projects、Gemini 文件分析 |
| C2 RAG 知识库产品 | 模型 + 文档解析 + Embedding + 向量库 + Reranker，反复根据指定资料回答并标明依据 | NotebookLM、Dify Knowledge Base、FastGPT、Coze 知识库、阿里云 RAG Agent、Glean |
| C3 搜索／深度研究产品 | 模型 + 网页搜索 + 来源筛选 + 引用/报告生成，用于最新信息和多来源研究 | Perplexity、ChatGPT Search/Deep Research、Gemini Deep Research、Kimi 搜索、豆包搜索 |
| C4 智能体产品 | 模型 + 规划 + 工具调用 + 观察反馈，把多步目标推进下去 | ChatGPT Agent、Manus、Coze Agent、Dify Agent、OpenClaw |
| C5 Skills／插件系统 | 把一组提示词、脚本、工具权限或专业流程封装为可安装、可复用的能力单元 | OpenClaw Skills、Coze 插件/技能、Dify Plugins、ChatGPT GPTs、Claude Skills |
| C6 无代码工作流平台 | 用画布把触发条件、模型、知识库、工具和人工确认连成固定流程 | Coze Workflow、Dify Workflow、n8n、Make、Zapier、Power Automate |
| C7 开发框架与运行时 | 面向开发者，用代码定义 Agent、工作流、状态、工具和长期运行机制 | LangChain、LangGraph、LlamaIndex、AutoGen、CrewAI、Semantic Kernel |

### 画图提示

- 将 A、B、C 三层画成从左到右的三列。A、B 的节点通过箭头指向 C，而 C 中的产品可以再指向“学习助手、写作助手、编程助手”等具体场景。
- 同一个产品可以有多条箭头。例如 Coze 可同时落在 C4、C5、C6；NotebookLM 主要落在 C2；Kimi 主要落在 A1 对应的聊天产品与 C1/C3。
- B 层只画图标和一句白话，不要求高中生记住具体技术名或安装方式；重点是让他们知道“产品能读讲义/联网/写日历，背后多了一套组件”。

## 三、贯穿案例任务卡：每个叶节点在“考前物理复习助手”中的位置

活动方式：每组抽 2–3 张卡，先判断它属于 A、B 还是 C 层；若是 B 层，再追问“它会被哪个 C 层产品调用”。学生不需要操作 B 层工具。

| 编号 | 具体情境或投影请求 | 学生应得出的选择判断 |
| --- | --- | --- |
| A1 文本通用模型 | “我总分不清电路分析和电磁感应。请用高中生能懂的语言解释区别，再出一道只考区别的选择题。” | 普通文本对话即可；答案仍与教材核对。 |
| A2 推理模型 | “我有 5 天、每天 45 分钟，第 3 天不能复习。比较两种复习安排，选一种并检查总时长。” | 条件多、需取舍时选思考模式或推理更强的模型；不把它的分析过程当作正确保证。 |
| A3 代码模型 | “生成可运行 Python，批量计算 10 组串并联电阻练习题的答案，再排成表格。” | 代码模型负责写程序；是否真的算对，要交给 B7 的执行环境验证。 |
| A4 视觉模型 | “读出这张手写错题的题干和我的步骤；看不清处标【不确定】；再判断可能从哪一步漏条件。” | 需图片输入和 OCR/视觉理解；先核对转写文本。 |
| A5 语音模型 | “我用 90 秒口述楞次定律。请转写、指出三个术语不准确处，再读出修正版。” | 语音输入/输出；录音是个人信息，课后删除。 |
| A6 图像模型 | “生成一张‘导体棒切割磁感线’复习卡，只标必要物理量。” | 图像工具用于记忆线索，图中箭头方向必须由教材或教师校验。 |
| A7 视频模型 | “制作 15 秒动画：先展示磁通量变化，暂停让同学预测，再揭示感应电流方向。” | 视频用于课前/课后材料，不以视觉效果替代物理理解。 |
| B1 文本 Embedding | 老师问：“为什么知识库能在几百页讲义中找到‘电流方向与磁场方向混淆’相关段落，即使学生没有输入完全一样的词？” | 它比较的是文本 Embedding 的相近程度；学生只需理解为“按意思找”，不必使用该模型。 |
| B2 多模态 Embedding | “把实验装置照片放进资料库后，能否找到构造相似的装置图和对应讲解？” | 可能使用图像/多模态 Embedding；这是以图搜图或多模态检索的幕后工具。 |
| B3 Reranker | “系统先找出 20 段都提到‘感应’的讲义，为什么最后只给我 3 段？” | Reranker 可能把最符合当前问题的片段排到前面；仍可能排错，所以要查看原文。 |
| B4 向量数据库 | “老师把整学期讲义和答疑放入复习助手。下个月再问同类问题，它为什么还找得到？” | 向量库保存资料的检索索引；它不是模型记住了整本讲义，更不是永久记忆学生隐私。 |
| B5 文档解析/OCR | “一张扫描版讲义有双栏文字、表格和公式。AI 回答前，第一步要做什么？” | 先用解析/OCR 取出文字和结构；解析错会连带导致 RAG 回答错。 |
| B6 网页搜索 API | “核对本省考试院是否发布了新通知，并列出原文链接和发布日期。” | 上层搜索产品会调用搜索工具；优先考试院/学校官网，不把论坛转述当依据。 |
| B7 代码执行沙箱 | “根据错题 CSV 统计电路、电磁感应、力学三类的错误率，画柱状图。” | 应实际运行代码/表格计算，而不是要求模型口算；先对数据脱敏。 |
| B8 外部系统 API | “把已确认的 5 天计划写入我的日历，但不读取其他日程。” | 日历 API 在授权后执行；模型能写计划不等于天然有日历权限。 |
| B9 MCP 服务 | “复习助手要同时读资料、查校历、运行统计。为什么不必为每个模型重新开发一遍这些连接？” | MCP 可用较统一的方式提供多种工具；只接入可信来源，并限制可用工具与权限。 |
| C1 文件阅读产品 | “请**只依据上传的复习讲义**列考试范围，每一点标页码；讲义未写的内容要明确说不知道。” | 选文件阅读/长文档产品；适合少量、一次性资料，不等于建立了知识库。 |
| C2 RAG 知识库产品 | “从‘本班讲义、老师答疑、已批改错题解析’中找 3 段依据，再出变式题并附来源。” | 选 RAG/知识库产品；先看命中的原文，检索不到不等于资料中不存在。 |
| C3 搜索／深度研究产品 | “只检索教育主管部门和考试院近两年公开文件，比较实验题评分要求是否变化，形成带引用核对清单。” | 简单最新通知用搜索；多来源、低频、复杂比对才开深度研究。最终判断交给老师。 |
| C4 智能体产品 | “先诊断两类薄弱点，再生成 5 天计划；每天根据 3 道自测题调整。连续两天低于 60% 时停止自动加量并建议问老师。” | 需要能规划、调用知识库/数据工具、根据结果调整的智能体。 |
| C5 Skills／插件系统 | “给复习助手安装‘错题统计’技能：输入 CSV，固定输出分类规则、图表和三条复习建议。” | Skill/插件封装的是可重复的专业流程；安装前看它会访问什么数据、会调用什么工具。 |
| C6 无代码工作流平台 | “每天 20:00 生成当日复习卡；仅在学生确认后更新个人进度表；周日生成只给本人看的总结。” | 固定、重复的流程可用 Coze/Dify/n8n 等编排；先用虚拟数据测试。 |
| C7 开发框架与运行时 | “学校要做一个能暂停、恢复、记录工具调用，并在写日历前让教师审批的复习助手。” | 开发者可用 LangGraph 等框架；高中课堂只需看懂它把模型、工具、状态和人工确认组织起来。 |

## 四、附件中五个情境的推荐行课顺序

| 情境 | 先让学生选什么 | 最后揭示的谱系关系 |
| --- | --- | --- |
| 解释知识 | 普通对话还是思考模式？ | A1；条件复杂才切换 A2。 |
| 依据指定讲义复习 | 普通聊天还是文件阅读产品？ | C1；其中会用到 A4/B5 等组件。 |
| 识别手写错题 | 纯文字聊天够不够？ | A4；照片处理还可能先经过 B5 OCR。 |
| 查询最新考纲 | 模型记忆还是搜索产品？ | C3 调用 B6；必须查正式来源。 |
| 写入复习日历 | 生成计划和写入日历是一回事吗？ | A1/A2 生成计划，C4/C6 可编排，B8 真正写入；人确认。 |

收束板书：

```text
任务 → 选择 C 层产品 → 看它用哪类 A 层模型和 B 层工具 → 检查资料、权限与结果
```

## 五、可放在课件最后一页的选型口诀

```text
要解释，选对话；条件多，再思考。
要读讲义，选文件；资料多、反复问，选知识库。
要最新，选搜索；要比较多来源，再做深度研究。
要看图，选多模态；要统计，让代码真运行。
要办事，找智能体或工作流；会改外部信息，必须人确认。
```

## 六、备课核验链接

- [Kimi 官方产品页](https://kimi.moonshot.cn/download/app)列举了对话、长文本、文件阅读与联网搜索等入口。
- [ChatGPT 文件工作官方说明](https://openai.com/academy/working-with-files/)和[Deep Research 帮助中心](https://help.openai.com/en/articles/10500283-deep-research-faq)适合核验 C1 与 C3 的产品形态。
- [Gemini Deep Research 官方帮助](https://support.google.com/gemini/answer/15719111)说明研究产品可组合搜索、文件和个人数据源。
- [Qwen Function Calling 官方文档](https://www.alibabacloud.com/help/en/model-studio/qwen-function-calling)展示模型请求工具、应用执行、结果返回模型的链路。
- [阿里云 RAG 能力说明](https://www.alibabacloud.com/help/doc-detail/3021892.html)可核验 B1、B3、B5、B4 在 RAG 中的作用。
- [LangChain 对 MCP 的说明](https://docs.langchain.com/oss/python/langchain/mcp)说明 MCP Server 可将可执行工具提供给 Agent 或工作流；接入前须审查其权限与可信度。
