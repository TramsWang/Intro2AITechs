# 课程设计

## 1. 课程总路线设计

### 1.1 课程总目标

本 8 课时版本由原“1-1 大模型基础”和“1-2 智能体基础”重组而成，目标不再是完整铺开人工智能发展史、机器学习通论和智能体平台工程，而是让高中生先建立一套能指导真实使用的 AI 判断框架。

完成本模块后，学生应能够初步做到：

1. 判断自己使用的 AI 工具属于聊天生成、搜索增强、文件问答、多模态处理、工具调用还是智能体系统；
2. 区分模型能力、产品功能和外部工具：模型本身不等于联网、文件读取、长期记忆或自动执行；
3. 用预测下一个 token、上下文、概率和随机性解释大模型为什么能聊天、为什么回答会变化；
4. 用 token、embedding 和多模态 token 解释输入怎样进入模型，以及为什么长文档、图片/语音输入、字数统计和字符级任务容易出错；
5. 用注意力、上下文窗口、算力、模型大小、训练数据和产品设计解释常见错误；
6. 根据任务复杂度、时效性、上下文长度、多模态需求、隐私、成本和安全要求进行初步模型选型；
7. 能把模糊需求改写成包含任务、要求、格式和场景的提示词，并根据输出问题迭代；
8. 能把复杂任务拆成规划、执行、搜索/RAG/代码等工具调用、反馈和人工确认环节；
9. 能围绕“考前知识点复习助手”设计一个简单智能体方案，说明模型、提示词、RAG、工具、记忆、评估和安全边界怎样协同工作。

### 1.2 贯穿案例

整套课程统一采用“考前知识点复习助手”作为贯穿案例。

案例设定为：学校希望设计一个受老师监管的 AI 学习支持智能体，帮助学生在考试前整理复习目标、定位薄弱知识点、生成复习计划和自测题。它不能替代老师做最终评价，也不能保证成绩提升，但可以辅助学生把复习任务拆清楚、把资料组织好，并把不确定或高风险内容交给人确认。

贯穿课堂的示例请求为：

```text
下周三要考物理，我对电路分析和电磁感应总是混淆。每天晚上大概有 45 分钟复习时间。请帮我整理重点、安排 5 天复习计划，并给我几道自测题。
```

这个案例在 8 节课中的作用如下：

| 课次 | 复习助手案例承担的作用 |
| ---- | ---------------------- |
| 第1课 | 判断它是聊天工具、学习助手还是智能体雏形，并分析需要哪些模型和产品能力。 |
| 第2课 | 对比模糊请求和结构化请求的输出差异，理解上下文和提示词为什么影响回答。 |
| 第3课 | 解释文字、公式、长文档和多模态输入如何被切分、向量化，并用 RAG 说明 embedding 怎样匹配语义相近资料。 |
| 第4课 | 分析复习助手为什么会漏考试范围、混淆概念、算错题或忽略时间限制。 |
| 第5课 | 比较不同模型和产品为什么在出题、讲解、规划、工具使用和安全提醒上表现不同。 |
| 第6课 | 把模糊复习需求改写成高质量提示词，并学会迭代输出。 |
| 第7课 | 设计复习助手如何规划任务、使用思考模式和 CoT/ToT、调用搜索/RAG/代码工具并根据反馈调整。 |
| 第8课 | 学生分组设计复习助手智能体方案，并用小龙虾/OpenClaw 案例理解真实智能体系统。 |

### 1.3 8 节课路线

| 节次 | 主题 | 核心问题 | 作用 |
| ---- | ---- | -------- | ---- |
| 第1课 | 你每天在用的 AI 到底是什么 | 我正在用的是模型、产品、工具还是智能体？ | 建立全局地图和模型选型入口 |
| 第2课 | AI 为什么能聊天 | 大模型为什么能一句接一句生成回答？ | 建立生成机制和提示词入门 |
| 第3课 | Token 是什么 | 语言、多模态输入和问题怎样进入模型？ | 建立 token、embedding、上下文和多模态 token 的连接 |
| 第4课 | 为什么 AI 有时“很蠢” | 为什么会漏条件、算错、忘前文或被无关信息带偏？ | 用注意力、上下文、算力和模型大小解释错误 |
| 第5课 | 不同 AI 为什么表现不同 | 为什么不同模型、版本和产品回答差异很大？ | 理解训练、对齐、工具和产品设计带来的能力差异 |
| 第6课 | 怎样让 AI 听你的 | 怎样把模糊需求变成可执行提示词？ | 形成结构化提示词与迭代能力 |
| 第7课 | AI 怎样完成复杂任务 | 一次问答怎样升级为规划、工具、反馈和调整？ | 学习 PaE、ReAct、思考模式、CoT/ToT 和工具调用 |
| 第8课 | 面对任务你有多少种解法 | 怎样设计一个复习助手智能体？ | 综合设计智能体方案并建立任务解法框架 |

课程顺序服务于学生真实使用 AI 的过程：

```text
先知道自己在用什么
  ↓
再知道它为什么会生成回答
  ↓
再知道语言和多模态输入怎样进入模型
  ↓
再知道它为什么会犯错、变慢、变贵或漏条件
  ↓
再知道不同模型和产品为什么能力不同
  ↓
再学习怎样把需求说清楚
  ↓
再学习怎样让 AI 做复杂任务
  ↓
最后设计一个复习助手智能体方案
```

## 2. 每节课简要设计

### 2.1 第1课：你每天在用的 AI 到底是什么

本课是全局导航课。学生从聊天助手、搜索增强问答、拍照识图、语音助手、短视频推荐、翻译、写作助手、代码助手和学习规划工具出发，建立人工智能、机器学习、深度学习、大语言模型、多模态模型、RAG、工具调用和智能体之间的关系。

本课重点区分“模型”和“产品”：同一个模型可以被包装成聊天、搜索、文件问答或学习助手；同一个产品也可能调用多个模型和工具。学生还要建立初步模型选型意识：简单整理用快模型，复杂推理用强推理模型，长文档用长上下文或 RAG，多图像/语音任务用多模态模型，隐私敏感任务要关注本地化、权限和数据边界。

### 2.2 第2课：AI 为什么能聊天

本课回答“大模型为什么能一句接一句地说话”。学生用“接下一句话”体验预测后续内容，理解大模型不是从固定答案库复制回答，而是在当前上下文中连续生成。课堂讲清概率分布、随机性、温度/top-p 的直觉，以及“流畅不等于正确”的幻觉风险。

本课同时前置提示词入门：既然模型根据上下文生成后续内容，用户给出的任务、要求、格式和场景就会直接影响输出。学生初步学会用提示词四要素和四原则改写简单问题。

### 2.3 第3课：Token 是什么

本课回答“语言和多模态输入怎样进入模型”。学生理解计算机处理的是数字，文本会被切成 token，token 会转成编号，再进入 embedding 向量空间。token 不等于字，也不一定等于词；中文词语、英文单词、数字、标点、空格和特殊符号都可能影响模型看到的输入。

本课还补充多模态模型中的 token 直觉：图片、声音和视频也会变成模型可处理的片段，消耗通常和分辨率、细节模式、图片数量、音频/视频时长以及产品实现有关。同时讲 embedding 也是产品能力，区分 token embedding 和文本段落 embedding，并把 RAG 作为典型应用：用 embedding 匹配语义相近的资料片段，再让大模型基于片段回答。学生由此理解长文档、上下文成本、字母计数、精确字符任务、多模态输入成本和 RAG 增强回答依据的基本逻辑。

### 2.4 第4课：为什么 AI 有时“很蠢”

本课用注意力、上下文和算力限制解释学生最常见的使用困惑。学生从漏条件、算错题、前后矛盾、长文档遗漏、关键词误判等案例出发，理解模型会给不同 token 分配关注权重，但注意力不是意识，只是计算中的权重分配。

本课还讲大模型和小模型的使用差异：大模型通常更全面、推理和泛化更强，但成本高、速度慢；小模型更快更便宜，适合固定任务，但复杂推理和长上下文可能弱。学生形成错误排查思路：提示词是否模糊、上下文是否缺失、材料是否太长、格式是否混乱、任务是否需要工具、模型是否不适合。

### 2.5 第5课：不同 AI 为什么表现不同

本课解释不同模型、版本、开源/闭源模型和产品为什么表现不同。学生复习训练和推理的区别，简化理解机器如何从数据中学习：模型看大量样本和目标，通过错误反馈调整参数，形成可迁移的规律。

课堂重点讲预训练、指令训练和聊天对齐的差异：基座模型会续写，指令模型会按任务回答，聊天模型更适应多轮对话和安全要求。学生还要理解产品差异：能联网、能读文件、能看图、能运行代码，不一定是模型本身更聪明，也可能是产品接了工具。

### 2.6 第6课：怎样让 AI 听你的

本课进入直接使用技巧。学生对比“帮我复习物理”和完整复习请求，复习提示词四要素和四原则，并学习角色设定、样例提示、分步提示、结构化输出、选择对话上下文五种技巧。

本课强调提示词迭代：观察输出问题，补充约束，要求自检，再测试。学生还会学习常见错误排查模板：输出太泛、格式不对、漏条件、编造事实、过度自信、前后矛盾时分别怎样改提示词。

### 2.7 第7课：AI 怎样完成复杂任务

本课讲“从一次问答到复杂任务”的跨越。学生知道复杂任务不能只靠一次提示词，而需要规划、执行、思考模式、CoT/ToT 提示引导、工具、观察结果和反馈调整。

课堂讲 PaE：先 Plan，再 Execute；讲 ReAct 的课堂版：判断依据、行动、观察/评估、反思调整。新增“思考模式/推理模式”的使用判断：它不是模型有意识，而是在推理时投入更多中间计算、步骤拆解、候选比较和自检。本课还补充 CoT 和 ToT：前者用 Prompt 引导模型分步骤分析，后者用 Prompt 引导模型先列多个方案再比较选择，并区分“提示词中的思考引导”和“模型原生思考模式”的差异。学生学会判断什么时候值得打开思考模式，什么时候应该用 CoT/ToT 组织 Prompt，什么时候应该优先搜索、RAG、代码或人工确认。

### 2.8 第8课：面对任务你有多少种解法：复习助手智能体设计

本课是收束课。学生围绕“考前知识点复习助手”设计一个学习支持智能体方案，说明目标用户、输入信息、输出成果、模型选型、提示词结构、需要的工具、记忆内容、评估标准和安全边界。

课堂引入小龙虾/OpenClaw 案例，说明真实智能体可以连接聊天入口、Gateway、Agent、模型、工具、插件、技能、会话、记忆和设备能力。学生不需要掌握部署细节，只需要看到：智能体不是孤立聊天框，而是模型、提示词、规划、工具、知识库、记忆、权限和评估共同组成的任务系统。

## 3. 整体教学风格设计

### 3.1 固定课型

每节课采用稳定结构：

1. 前一节课内容回顾：约 3 分钟，承接上一节核心概念和课后作业；
2. 内容引入：约 3 分钟，用学生熟悉的场景提出本节问题；
3. 知识点讲授：约 20 分钟，用案例、类比、表格和简化流程讲清少量核心概念；
4. 互动强化：约 20 分钟，用游戏、分组讨论、提示词改写、流程设计、找茬或方案审查，让学生直观体会讲授内容；
5. 课后提升：约 20 分钟，保留一个动手型小作业，并增加一个可选的选择题/问答题模式，方便授课条件有限的老师使用。

### 3.2 三少三多

少公式，多类比：用“接下一句话”“桌面材料”“词语站位”“调度员和工具”“复习计划卡”等方式解释抽象概念。

少工程细节，多使用判断：不要求学生掌握训练工程、MCP 协议细节、OpenClaw 部署或插件开发，而是让学生知道什么时候要查资料、什么时候要用工具、什么时候必须人工确认。

少单向讲授，多互动体验：每节课都让学生在分类、改写、检索模拟、错误排查、工具调度或智能体设计中把概念变成可操作经验。

### 3.3 贯穿的安全与责任边界

本模块持续强调：

- 流畅不等于正确；
- 搜索结果、RAG 检索和代码执行都需要检查；
- 模型不能替代老师做最终评价；
- 复习助手不能承诺一定提高成绩；
- 不能生成或传播考试答案；
- 学生隐私、成绩记录、错题本和长期记忆需要授权、最小化保存和可删除机制；
- 高风险内容应转交老师、家长或相关成年人处理。

## 4. 最终学生应达到的理解水平

学完后，学生不需要会训练模型或开发完整智能体，但应该能用自己的话解释：

> 我知道自己使用的 AI 工具大概属于哪种产品形态，也知道模型、产品和工具不是一回事。大模型通过 token 和 embedding 把语言变成数字，多模态模型也会把图片、声音和视频变成可计算的输入片段，并在上下文中预测下一个 token 来生成回答；注意力帮助它找重点和关系，但它仍受上下文、算力、训练数据、工具能力和产品设计限制。不同模型表现不同，不能只看宣传，要根据任务选择合适模型和工具。使用时，我会把任务、要求、格式和场景写清楚，必要时让 AI 分步规划、搜索公开信息、调用 RAG、读取指定文件或执行代码，并对输出做事实核查、格式检查、风险判断和人工确认。面对贯穿课程的复习助手任务，我能说明它为什么属于智能体，以及它怎样整合模型、提示词、RAG、工具、记忆、评估和安全边界。

最终形成的 AI 使用判断框架是：

```text
看任务
  ↓
选产品/模型/工具
  ↓
写清提示词
  ↓
拆解复杂任务
  ↓
检查依据和风险
  ↓
复盘并改进
  ↓
设计复习助手智能体方案
```
