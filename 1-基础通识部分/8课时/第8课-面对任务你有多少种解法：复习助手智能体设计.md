# 第8课：面对任务你有多少种解法：复习助手智能体设计

## 前一节课内容回顾

**3 分钟回顾：从“复杂任务流程”到“智能体系统设计”**

上一节课我们学习了复杂任务怎样从一次问答升级为流程：PaE 先计划再执行，ReAct 让每一步都有判断依据、行动、观察/评估和反思调整；思考模式适合多步推理、方案权衡和复杂规划，但更慢、更贵，也不保证正确；搜索、RAG、代码、表格、日历和安全审核等工具能增强能力，但必须检查来源、参数、权限和人工确认点。

作业点评时，可表扬流程完整、人工确认点清楚的答案。例如优秀方案会把“读取错题本”“写入日历”“向老师发送学习情况”列为需要确认，把“不确定考试范围”标注为需要老师核实。教师承接本课：今天把前 7 课全部合起来，设计一个真正可说明结构、工具、记忆、评估和边界的复习助手智能体。

## 内容引入

**3 分钟互动：复习助手是一条提示词，还是一个系统？**

教师再次展示贯穿请求：

```text
下周三要考物理，我对电路分析和电磁感应总是混淆。每天晚上大概有 45 分钟复习时间。请帮我整理重点、安排 5 天复习计划，并给我几道自测题。
```

请学生判断：如果只写一条好提示词，它能完成哪些部分？如果要持续读取讲义、统计错题、记录进度、根据自测调整、写入提醒、保护隐私，它还需要哪些模块？

教师引出本课核心：智能体不是“更会聊天的大模型”，而是围绕目标持续完成任务的系统。

## 知识点讲授

### 1. 用复习助手回顾全课

复习助手把前 7 课内容串在一起：

- 第1课：判断它属于学习助手/智能体雏形，需要模型、产品和工具组合；
- 第2课：它根据上下文生成计划和自测题，提示词影响输出；
- 第3课：文字、公式、图片和语音会变成 token、embedding 或其他可计算输入片段；
- 第4课：它可能漏条件、算错或被无关信息带偏，需要错误排查；
- 第5课：不同模型和产品在规划、出题、工具调用和安全提醒上表现不同；
- 第6课：结构化提示词让任务、要求、格式、场景更清楚；
- 第7课：复杂复习任务需要 PaE、ReAct、思考模式、RAG 等工具和反馈。

### 2. 什么是智能体

本课采用的智能体定义：

> 智能体是围绕目标持续完成任务的系统，它把大模型、提示词、规划框架、工具、知识库、记忆、评估、权限和人工确认组织在一起。

智能体不是模型有了主观意识。它的能力来自系统设计：模型负责理解和生成，提示词负责约束任务，工具负责查资料和执行动作，记忆保存必要状态，评估和权限控制风险。

### 3. 复习助手的基本结构

一个受老师监管的复习助手可以包含：

| 模块 | 作用 | 风险控制 |
| ---- | ---- | -------- |
| 用户入口 | 接收学生请求和反馈 | 提醒不要输入无关隐私 |
| 任务理解 | 提取考试时间、科目、薄弱点、可用时间 | 信息缺失时追问 |
| 规划模块 | 拆成资料检索、复习安排、自测、反馈 | 步骤要可检查 |
| 模型调用 | 解释、生成、总结、比较方案 | 选择适合任务的模型 |
| RAG/课程知识库 | 检索老师讲义、复习范围、错题解析 | 标注来源和更新时间 |
| 错题记录 | 定位薄弱知识点 | 需授权，少保存敏感信息 |
| 题目生成工具 | 生成自测题和解析 | 防止生成考试答案 |
| 代码/统计工具 | 统计错题分布、时间安排 | 检查统计口径 |
| 日程工具 | 生成提醒或计划 | 写入前人工确认 |
| 安全审核 | 检查作弊、隐私、过度承诺和高风险内容 | 高风险转人工 |
| 反馈与记忆 | 保存进度和常见错因 | 可查看、可修改、可删除 |

### 4. 小龙虾/OpenClaw 案例

为了理解真实智能体系统，可以用“小龙虾/OpenClaw”作为案例。课堂中不要求学生掌握部署、Gateway 细节、插件开发或设备节点，只把它作为一个真实智能体系统的结构样例。

OpenClaw 可以被教学化理解为：一个能连接聊天入口、Gateway、Agent、模型、工具、插件、技能、会话、记忆和设备能力的个人智能体平台。

一个任务的流动可以简化为：

```text
用户在聊天入口提出任务
  ↓
Gateway 接收消息、确认身份和会话
  ↓
Agent 调用模型理解目标并规划
  ↓
模型判断需要工具、插件或技能
  ↓
工具执行并返回观察结果
  ↓
Agent 更新会话、记忆或下一步
  ↓
结果回到用户入口
```

这个案例说明：真实智能体不是一个孤立聊天框，而是多个模块协作的系统。

### 5. 对照 OpenClaw 和复习助手

OpenClaw 展示真实智能体可以接入渠道、模型、工具、记忆和设备能力。复习助手则把这些能力限制在学习场景中：

- 入口：学生和老师允许的学习平台；
- 模型：用于理解、解释、规划和生成题目；
- 工具：课程 RAG、错题统计、题库、日历、安全审核；
- 记忆：复习进度、常见错因、学习偏好；
- 权限：读取资料、保存记忆、写入日程都需要授权；
- 评估：准确性、依据、可执行性、隐私和安全边界。

能力越强，边界越重要。能自动完成，不代表应该自动完成。

### 6. 面对任务的解法路径

面对一个学习任务，学生可以先判断使用哪条路径：

| 解法路径 | 适用场景 |
| -------- | -------- |
| 直接问答 | 解释一个概念或术语 |
| 结构化提示词 | 生成复习计划、知识卡片、写作提纲 |
| 分步规划 | 安排多天复习、分阶段完成项目 |
| 多方案比较 | 比较按知识点、按错题、按题型复习 |
| 搜索增强 | 需要最新通知、报名时间、公开资料 |
| RAG/文件问答 | 必须基于老师讲义、错题解析或校内资料 |
| 代码/计算工具 | 统计错题、计算时间、处理表格 |
| 人工确认/转人工 | 考试范围不明确、隐私、作弊、正式评价、高风险压力 |

### 7. 评估 AI 输出和智能体过程

评估不只看答案像不像，还要看过程是否可靠：

- 准确性：知识点和计算是否正确；
- 完整性：是否覆盖目标和限制；
- 依据：是否标注资料来源；
- 可执行性：时间和步骤是否现实；
- 格式：是否便于学生使用和检查；
- 工具调用：工具是否选对，参数是否准确；
- 风险：是否涉及隐私、作弊、过度承诺或高风险建议；
- 人工确认：哪些地方需要老师、学生或家长确认。

## 互动强化

**20 分钟活动：复习助手智能体设计会**

活动目标：让学生把 8 节课内容综合成一个可说明、可检查、有边界的智能体方案。

### 小组任务

每组设计一个“考前知识点复习助手”，必须说明：

1. 目标用户；
2. 输入信息；
3. 输出成果；
4. 使用哪类模型；
5. 提示词结构；
6. 需要哪些工具；
7. 哪些资料进入 RAG；
8. 记忆哪些内容，不记忆哪些内容；
9. 怎样评估输出；
10. 哪些操作可以自动做、必须问人后做、完全不应该做。

### 三栏安全分类

每组填写：

| 可以自动做 | 必须问人后做 | 完全不应该做 |
| ---------- | ------------ | ------------ |
| 整理授权讲义、生成计划草案、自测题草案 | 读取错题本、保存长期记忆、写入日历、发送学习情况 | 承诺一定提分、生成考试答案、未经同意保存隐私、替代老师评价 |

### 活动流程

1. 5 分钟：小组填写设计卡；
2. 5 分钟：补充工具、RAG、记忆和人工确认点；
3. 5 分钟：用三栏表审查安全边界；
4. 3 分钟：每组用 1 分钟汇报最重要的一个设计选择；
5. 2 分钟：教师总结全课框架。

教师重点追问：

- 你们为什么选择这种模型或产品？
- 哪一步必须用 RAG，而不是让模型凭记忆答？
- 哪一步需要代码或统计工具？
- 哪些信息不能长期保存？
- 如果 AI 输出错了，怎样追踪是哪一步出错？

## 课后提升

**20 分钟小作业：完成一张复习助手智能体设计卡**

独立完成一张设计卡，内容包括：

1. 智能体名称和目标用户；
2. 输入信息和输出成果；
3. 模型选择理由；
4. 提示词结构；
5. 工具和知识库；
6. 记忆边界；
7. 评估标准；
8. 安全边界；
9. 可以自动做、必须问人后做、完全不应该做的事项。

**拓展任务：** 选择一个非物理学科，例如英语、历史、生物或数学，把复习助手设计卡改成对应学科版本。

**可选模式：20 分钟课堂内容回顾题**

选择题：

1. 智能体最准确的理解是：  
   A. 一个更会聊天的模型 B. 围绕目标持续完成任务的系统 C. 一个固定答案库 D. 一个只能画图的工具
2. 复习助手基于老师讲义回答问题，最适合使用：  
   A. RAG/课程知识库 B. 随机猜测 C. 删除资料 D. 只看模型名称
3. 下面哪项完全不应该让复习助手做？  
   A. 整理授权讲义 B. 生成自测题草案 C. 承诺一定提高成绩 D. 标注不确定内容

问答题：

1. 用自己的话解释复习助手怎样整合模型、提示词、RAG、工具、记忆和评估。
2. 小龙虾/OpenClaw 案例说明真实智能体有哪些组成部分？
3. 写出一个“可以自动做、必须问人后做、完全不应该做”的三栏示例。

参考答案：1-B，2-A，3-C。
