# 第7课：AI 怎样完成复杂任务

## 前一节课内容回顾

**3 分钟回顾：从“写清提示词”到“组织任务流程”**

上一节课我们学习了结构化提示词：任务、要求、格式、场景四要素，以及全面性、一致性、简洁性、合理性四原则。我们还学习了角色设定、样例提示、分步提示、结构化输出和选择对话上下文，并通过提示词迭代理解了“观察输出、找问题、改提示词、再测试”的过程。

作业点评时，可表扬能写出检查要求和迭代方案的答案。例如有同学不仅写“安排复习计划”，还要求每天不超过 45 分钟、先列混淆点、输出表格、无法确认范围要标注。教师承接本课：提示词能把一次回答说清楚，但如果任务需要调用课程 RAG、统计错题、生成计划、做自测、根据反馈调整，一次提示词就不够了。

## 内容引入

**3 分钟互动：一次问答，还是复杂任务？**

教师列出两类请求，请学生判断：

```text
1. 请解释什么是楞次定律。
2. 请根据我的错题记录和老师讲义，安排 5 天复习计划，生成自测题，收集我的答题结果，再调整后两天安排。
```

第一类通常一次回答就能完成。第二类需要持续推进：先理解目标，再调用课程 RAG 匹配讲义和错题资料，再统计错题，再计划，再出题，再根据反馈调整。

本节课核心：复杂任务需要规划、执行、思考模式、CoT/ToT 提示引导、工具调用、观察结果和反馈调整。

## 知识点讲授

### 1. 普通聊天和复杂任务的区别

普通聊天通常是一问一答。复杂任务则包含多个步骤、多个信息来源和多个检查点。

| 普通聊天 | 复杂任务 |
| -------- | -------- |
| 回答一个问题 | 围绕目标持续推进 |
| 主要生成文字 | 可能要调用 RAG、计算、写文件、调整计划 |
| 输出后结束 | 根据结果和反馈继续下一步 |
| 错误较容易发现 | 错误可能在流程中累积 |

复习助手如果只是解释“什么是电磁感应”，可以用普通提示词；如果要根据错题和讲义持续安排复习，就需要任务流程。

### 2. PaE：先计划，再执行

PaE 可以简化为：

```text
Plan 计划
  ↓
Execute 执行
```

Plan 阶段要提取：

- 目标：下周三物理考试；
- 背景：电路分析和电磁感应薄弱；
- 约束：每天 45 分钟；
- 资料：老师讲义、错题记录、复习范围；
- 工具：课程 RAG、错题统计、题库、日历；
- 交付物：5 天计划、自测题、需要确认的内容。

Execute 阶段按计划生成知识卡片、调用课程 RAG、统计错题、安排日程、生成自测题、整理错因，并输出结果。

### 3. ReAct 的课堂版

ReAct 可以理解为“判断依据 -> 行动 -> 观察/评估 -> 反思调整”的循环。课堂中不要求学生展示或复述模型内部完整思考，只要求任务过程可检查。

复习助手例子：

```text
判断依据：学生混淆电路分析和电磁感应，需要先定位混淆点。
行动：调用课程 RAG 和错题记录。
观察/评估：错题主要集中在楞次定律方向判断和串并联电路等效电阻。
反思调整：计划中应先安排概念对比，再安排专项练习。
行动：生成第 1-2 天复习内容和诊断题。
观察/评估：学生诊断题第 2 题出错。
反思调整：补充右手定则和楞次定律适用场景对比。
```

ReAct 的价值是：每一步有依据、行动和结果，出错时能追踪和调整。

### 4. 思考模式是什么

很多 AI 产品会提供“思考模式”“推理模式”或类似选项。它不是模型突然有意识，而是产品或模型在回答前投入更多推理计算，让模型进行更长的中间分析、步骤拆解、候选方案比较和自我检查，再输出最终答案。

可以直观对比：

| 普通模式 | 思考模式 |
| -------- | -------- |
| 更像看到问题后直接生成回答 | 更像先多走几步草稿、比较和检查流程 |
| 速度快、成本低 | 更慢、可能更耗额度 |
| 适合简单问答、翻译、润色、格式转换 | 适合多步推理、复杂代码、方案权衡、长链条规划 |
| 容易在复杂条件下漏步骤 | 通常更能拆解和检查 |

课堂中不要求学生看到模型完整内部思考。更合适的要求是让它输出可检查的步骤、依据、假设和结论。

### 5. 什么时候用思考模式，什么时候不用

适合打开思考模式：

- 多步数学和逻辑题；
- 复杂代码调试；
- 多方案权衡；
- 长链条规划；
- 需要严谨检查的答案；
- 容易被条件绕晕的问题；
- 需要先拆任务再执行的复习计划。

不必打开思考模式：

- 简单问答；
- 翻译润色；
- 格式转换；
- 短文本摘要；
- 低风险创意发散；
- 需要最新事实但更应该先搜索的问题；
- 已经有明确工具能直接计算或检索的问题。

局限也要清楚：思考模式更慢、更贵，不保证一定正确。如果资料缺失、提示词矛盾、问题本身有误，模型可能只是更认真地走向错误。事实核查、数学计算、代码运行和文件处理仍需要工具和人工确认。

### 6. CoT 和 ToT：用 Prompt 引导思考方式

除了在产品里打开“思考模式”，学生还可以在 Prompt 中明确要求模型采用某种思考方式，让输出过程更细、更可检查。这里介绍两种常见方式：CoT 和 ToT。

CoT 是 Chain of Thought，常译为“思维链”。课堂中可以把它理解为：不要让模型直接给结论，而是要求它先列条件、再分步骤分析、最后给答案。比如：

```text
请先列出已知条件和目标，再分步骤说明解题过程，最后给出结论，并检查是否遗漏每天 45 分钟的限制。
```

复习助手中，CoT 适合用在解题、错因分析、计划拆解和检查限制条件时。例如让 AI 讲一道电磁感应题，可以要求它按“已知条件 -> 适用规律 -> 方向判断 -> 易错点 -> 答案”的顺序输出。

ToT 是 Tree of Thoughts，常译为“思维树”。它不是只沿着一条思路往下走，而是先列出几种可能方案，再比较优缺点，最后选择更合适的一种。比如：

```text
请给出 3 种复习安排方案：按知识点复习、按错题复习、按题型复习。分别比较优点、风险和适用情况，再推荐最适合我的一种。
```

ToT 适合开放任务、方案选择和复杂规划，例如比较“先补概念再刷题”“先看错题再补概念”“每天混合复习”三种路径。

要注意，Prompt 中引导模型思考和模型原生的思考模式不是一回事：

| Prompt 引导思考 | 模型原生思考模式 |
| ---------------- | ---------------- |
| 用户在提示词里要求“分步骤”“多方案比较”“先自检” | 产品或模型在推理阶段投入更多内部计算 |
| 主要改变输出结构和任务流程 | 主要改变模型回答前的计算过程 |
| 学生可以看到步骤、依据和比较表 | 用户通常看不到完整内部过程 |
| 可用于普通模式，也可配合思考模式 | 是否可用取决于具体产品或模型 |

所以，更稳妥的写法不是要求模型“展示全部内心思考”，而是要求它输出可检查的依据、步骤、假设、方案比较和最终结论。CoT/ToT 能帮助模型组织回答，但不能保证事实正确；思考模式能投入更多计算，但也不能替代 RAG、搜索、代码和人工确认。

### 7. 工具调用怎样工作

工具调用不是模型自己真的打开浏览器或读取文件，而是：

```text
模型判断需要工具
  ↓
生成工具名称和参数
  ↓
外部程序执行工具
  ↓
工具返回结果
  ↓
模型基于结果继续回答
```

复习助手常见工具：

- 联网搜索：查最新通知、比赛报名时间、公开资料；
- RAG/课程知识库：检索老师讲义、错题解析、复习范围；
- 代码执行：统计错题分布、计算时间安排、画图；
- 表格处理：整理错题和复习进度；
- 图片/语音工具：识别手写题、实验装置图或语音提问；
- 日历和文件工具：创建提醒、保存计划，但需要确认；
- 安全审核：检查作弊、隐私、过度承诺和高风险内容。

### 8. 任务拆解原则

好的任务拆解应该满足三个条件：

1. 步骤有顺序；
2. 每一步能判断是否完成；
3. 缺信息时追问或暂停，而不是编造。

复习助手可拆成：

```text
1. 提取目标和限制；
2. 确认考试范围和资料来源；
3. 调用课程 RAG 和错题记录；
4. 统计薄弱知识点；
5. 安排 5 天计划；
6. 生成自测题；
7. 根据自测反馈调整；
8. 标注需要老师确认的内容。
```

### 9. 反馈和安全

复杂任务越能自动做事，越需要反馈和安全边界：

- 工具结果要看来源和参数；
- 搜索要优先权威来源；
- RAG 要检查片段是否完整、是否过时；
- 代码要检查统计口径和结果；
- 写入日历、发送消息、读取敏感文件前要人工确认；
- 涉及作弊、正式评价、隐私或严重心理压力时要转人工。

## 互动强化

**20 分钟活动：复习助手任务调度桌游**

活动目标：让学生体验复杂任务中“计划、工具、观察、调整”的流程。

### 活动材料

教师准备四类卡片：

- 任务卡：下周三考试、每天 45 分钟、电路和电磁感应薄弱；
- 工具卡：搜索、课程 RAG、错题统计、题库、自测反馈、日历、安全审核；
- 资料片段卡：讲义片段、错题解析片段、考试范围片段、无关片段或过期片段；
- 事件卡：老师讲义缺失、RAG 检索到无关片段、错题统计显示电路更多、学生自测第 2 题错、考试范围不确定、日历写入需确认。

### 活动流程

1. 每组先写出 Plan：目标、信息、步骤、工具、交付物。
2. 每组按步骤选择工具卡，说明工具名称和参数，例如“课程 RAG：检索电磁感应 易错点”。
3. 如果选择课程 RAG，教师发 2-3 张资料片段卡，小组判断片段是否相关、是否完整、是否需要继续检索。
4. 教师发一张事件卡，模拟工具返回结果或意外情况。
5. 小组根据资料片段卡和事件卡进入 ReAct：观察结果，判断是否完成当前目标，必要时调整计划。
6. 每组最后输出一份简化流程：

```text
目标 -> 步骤 -> 工具 -> 观察结果 -> 调整 -> 最终输出 -> 人工确认点
```

7. 教师抽取 2 组汇报，重点追问：哪一步需要思考模式？哪一步适合用 CoT 或 ToT 写进 Prompt？哪一步更应该用 RAG、搜索或代码？哪一步必须人工确认？

## 课后提升

**20 分钟小作业：为一个复杂学习任务写流程**

选择一个复杂学习任务，写出：

1. 目标和限制；
2. PaE 计划；
3. 至少两轮 ReAct 循环；
4. 需要哪些工具；
5. 哪些步骤适合思考模式；
6. 哪些步骤适合用 CoT 分步骤分析，哪些步骤适合用 ToT 比较多个方案；
7. 如果使用 RAG，需要检索什么资料、如何检查片段是否可靠；
8. 哪些操作必须人工确认。

**拓展任务：** 把你的流程改写成一条给 AI 的结构化提示词，要求它先列计划，再执行第一步。

**可选模式：20 分钟课堂内容回顾题**

选择题：

1. PaE 指的是：  
   A. 先计划再执行 B. 先删除再训练 C. 先联网再关机 D. 先翻译再绘图
2. 思考模式更适合：  
   A. 简单格式转换 B. 多步推理和复杂规划 C. 只改标点 D. 单词翻译
3. ToT 更适合用于：
   A. 直接抄写一个答案 B. 比较多个复习方案后选择 C. 删除所有依据 D. 只做单词翻译
4. 工具调用的正确理解是：
   A. 模型自己打开所有软件 B. 模型生成调用请求，外部工具执行并返回结果 C. 工具不需要权限 D. 工具结果永远正确
5. RAG 工具更适合用于：
   A. 永久训练模型 B. 基于老师讲义和错题解析回答 C. 删除所有来源 D. 替代人工确认

问答题：
