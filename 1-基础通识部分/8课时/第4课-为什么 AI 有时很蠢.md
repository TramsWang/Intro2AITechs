# 第4课：为什么 AI 有时“很蠢”

## 前一节课内容回顾

**3 分钟回顾：从“语言进入模型”到“模型怎样看重点”**

上一节课我们学习了 token、编号、embedding 和多模态 token。文字进入模型前会被切成 token，再变成向量；embedding 让语义关系可以被计算；图片、声音和视频也会变成模型可处理的输入片段，消耗和分辨率、数量、时长、细节要求等因素有关。

作业点评时，可表扬能标注输入风险的答案。例如优秀作业会说明“手写题照片越多、越模糊，识别和处理成本越高；长文档要先分段或提取要点；精确字母计数要特别检查”。教师承接提问：既然模型能处理 token、向量和不同输入，为什么它有时还是会漏条件、算错题、忘前文，甚至像没看懂一样？

## 内容引入

**3 分钟互动：这份复习计划哪里蠢？**

教师展示一段明显有问题的 AI 回答：

```text
你下周三考物理，每天有 45 分钟。建议你每天复习 2 小时，重点背诵英语单词，最后一天刷 100 道电磁感应题。电路分析和电磁感应都差不多，放在一起背公式就行。我保证这样可以提高成绩。
```

请学生快速找错：

- 忽略每天 45 分钟限制；
- 把物理复习混进英语单词；
- 把电路和电磁感应粗暴混同；
- 任务量不现实；
- 过度承诺成绩提升。

教师引出本课：AI 看起来“蠢”时，往往不是一个原因，而是上下文、Transformer、注意力、算力、任务类型、模型能力和工具缺失共同造成的。

## 知识点讲授

### 1. 常见“很蠢”错误可以分类

复习助手常见错误包括：

| 错误表现 | 可能原因 |
| -------- | -------- |
| 漏掉“每天 45 分钟” | 关键限制没有被充分关注，或被大量信息淹没 |
| 把电路和电磁感应混为一谈 | 上下文关系理解不够细 |
| 算错复习时间总量 | 口头推理不适合精确计算 |
| 编造考试范围 | 没有资料来源却想给完整答案 |
| 长文档只回答后半部分 | 上下文窗口和信息位置影响 |
| 输出格式不按要求 | 指令冲突或格式约束不够清楚 |
| 过度自信 | 对齐和生成目标让模型倾向给出完整答案 |

### 2. 上下文决定词语含义

同一个词在不同上下文中含义不同。“电路”可能是物理知识点，也可能是电子工程项目；“方向”可能指电流方向、磁场方向，也可能指复习方向。

模型不能只看孤立 token，而要结合前后关系。复习助手处理“我对电路分析和电磁感应总是混淆”时，应该理解这是两个相邻但不同的物理知识点，而不是把它们当成同一类公式背诵任务。

### 3. Transformer：大模型处理上下文的核心部件

现代大语言模型通常把 Transformer 作为核心部件。上一节课讲过，文字会先变成 token 和 embedding 向量；进入模型后，Transformer 会让这些 token 在当前上下文里互相“看一看”，判断谁和谁更相关。

可以这样理解：

```text
token 和 embedding
  ↓
进入 Transformer
  ↓
在上下文中比较 token 之间的关系
  ↓
形成更适合生成回答的表示
```

同一个 token 进入 Transformer 后，不再只代表孤立词语，而会带上上下文信息。例如“电路”在“电路分析”和“电磁感应总是混淆”附近时，更可能被理解为物理复习知识点；如果它出现在“开发一块电路板”附近，含义和任务重点就会变。

Transformer 的关键能力之一，就是通过注意力机制高效寻找上下文中词语之间的关联。

### 4. 注意力机制：找重点和关系

注意力机制可以类比为学生听课时抓重点。学生不会平均关注黑板上的每一个字，而会把注意力放在关键词、公式、条件和问题上。模型在处理某个 token 时，也会给上下文中其他 token 分配不同关注权重，用来判断哪些信息更相关。

例如处理“安排 5 天复习计划”时，模型应该关注：

- “下周三要考物理”；
- “电路分析和电磁感应总是混淆”；
- “每天晚上大概有 45 分钟”；
- “整理重点、安排计划、自测题”。

如果注意力没有充分利用这些限制，输出就可能漏条件。

注意力机制的价值不是“看起来像人”，而是让模型能在较长文本中更快地找到关联：谁限制了时间，谁说明了学科，谁指出了薄弱点，谁规定了输出任务。这个过程可以类比为人类注意力，但本质仍然是计算。

### 5. 注意力不是意识

这里的“注意力”只是计算中的权重分配，不代表模型真的像人一样有主观意识或理解动机。模型可以学会在文本中找关联，但它不会自动知道哪些结果会对学生产生真实影响。

因此，输出仍需要人类检查，尤其是学习评价、隐私、安全、考试公平和心理压力相关内容。

### 6. 上下文窗口和算力限制

模型一次能处理的信息有限，这个范围常叫上下文窗口。可以把它想象成模型当前摊在桌面上的材料：桌面上有的材料可以参考，桌面外的材料就难以利用。

上下文窗口和算力限制也和 Transformer 有关。Transformer 要在上下文中比较 token 之间的关系，上下文越长，需要参与比较和整合的信息越多，计算量、显存占用、等待时间和成本通常也会增加。

长材料还可能带来两个问题：

- 关键条件被淹没在大量无关文字里；
- 前后材料互相冲突，模型不知道该听哪一段。

所以使用大模型时，不是“把所有材料都塞进去”就最好，而是要整理、分段、提取重点，必要时使用 RAG 从指定资料中匹配相关片段。

### 7. 大模型和小模型的直观差异

大模型通常参数更多、能力更全面，在复杂推理、长文本理解、泛化和多步骤规划上更有优势，但成本更高、速度更慢。

小模型通常更快、更便宜，适合固定、低风险、高频任务，例如分类、格式转换、简单摘要、固定问答。但面对复杂推理、长上下文、多工具协作时可能更容易出错。

模型越大不一定永远更适合。任务简单、低风险、需要快速批量处理时，小模型或快模型可能更合理；任务复杂、约束多、风险高时，才更需要强模型、工具和人工确认。

### 8. 错误排查方法

看到 AI 输出异常时，可以按下面顺序排查：

1. 问题是否太模糊？
2. 关键上下文是否缺失？
3. 关键条件是否放得太靠后或被无关信息淹没？
4. 材料是否太长，需要分段、摘要或后续检索工具？
5. 任务是否需要计算器、代码、搜索或课程 RAG？
6. 模型是否不适合这个任务？
7. 输出是否涉及事实、隐私、安全或正式评价，需要人工确认？

改进方法包括：把条件前置、删掉无关上下文、分段处理、要求模型复述约束、让模型先列检查清单、必要时调用工具。

## 互动强化

**20 分钟活动：复习助手错误诊断赛**

活动目标：让学生把“Transformer、注意力、上下文、算力、模型大小、工具缺失”转化为实际排查能力。

### 活动材料

教师准备 4 段复习助手错误回答，每段突出一种问题：

1. 漏掉“每天 45 分钟”；
2. 编造老师考试范围；
3. 把电路和电磁感应混为一谈；
4. 对错题统计进行错误心算；
5. 输出计划过长、格式混乱或没有自测题。

### 活动流程

1. 每组拿到一段错误回答，先标出最严重的 2 个问题。
2. 小组判断错误类型：提示词不清、上下文缺失、关键条件被淹没、需要工具、模型能力不足、事实来源缺失或安全边界问题。
3. 小组写出一条改进策略，例如“把每天 45 分钟放到提示词前面”“要求先复述限制条件”“需要基于老师讲义检索”“统计错题应使用表格或代码”。
4. 小组把原提示词改写成更可靠版本。
5. 教师抽取 2-3 组展示，追问：你们的修改是让模型更关注条件，还是把任务交给了更合适的工具？
6. 全班形成一张“AI 错误排查清单”。

### 设备替代方案

有设备时，学生可以测试改写前后的输出；无设备时，用教师准备的错误回答和理想回答对比即可。

## 内容问答

1. 学生可能会问：AI 明明前面答得很好，为什么突然犯低级错误？

   推荐回答：模型生成是一步步进行的，长对话里可能受上下文长度、关键信息位置、指令冲突和前面错误影响。它不是每一步都会像人一样重新审题，所以复杂任务中要让它复述限制、分步检查、必要时使用工具。

2. 学生可能会问：注意力机制是不是说明模型真的会“注意”和“理解”？

   推荐回答：这里的注意力是计算权重，不是人的主观注意。它能帮助模型判断哪些 token 更相关，但不代表模型有意识、动机或真实理解后的责任判断。

3. 学生可能会问：上下文窗口越大，是不是就可以把所有资料都塞进去？

   推荐回答：不建议这样做。窗口大只是能放更多材料，不代表模型一定会用好所有材料。无关信息、重复信息和冲突材料会增加干扰，关键资料仍然需要整理、分段、标注来源和突出限制。

4. 学生可能会问：大模型是不是一定比小模型好？

   推荐回答：复杂推理、长文本、多步骤规划通常更适合强模型；但简单分类、格式转换、批量摘要等任务，小模型可能更快、更便宜。模型大小只是因素之一，还要看任务风险和工具配合。

5. 学生可能会问：AI 算错题时，我应该先改提示词还是换工具？

   推荐回答：如果是解题步骤不清，可以先改提示词，让它列条件和检查过程；如果涉及大量计算、统计或精确数值，应该用计算器、代码或表格工具验证。不要只靠语言模型口头心算。
